# Pickaroo: handover

Written 2026-11-17 for whoever takes over. It tells you what exists, how to run it, what is merged, what is in flight, what to do next, and the traps we hit. The plan with the original reasoning is in `PLAN.md` (same folder); the rules for working in the repos are in `CLAUDE.md`.

## 1. What Pickaroo is

A grocery marketplace: customers order from stores (pickup or delivery), staff run their store, drivers deliver. Every store is its own business with its own catalog, stock and owner (decision of 2026-11-16).

Three repositories, all under `github.com/Carlo068/`:

| Repo | What | Stack |
|---|---|---|
| `PickarooAPI` | The backend. One GraphQL endpoint (Apollo Gateway :4000) over two subgraphs: `mongoAPI` (:4001: catalog, stores, carts, orders, auth, roles, drivers) and `auditAPI` (:4003: audit log). | Node 24, MongoDB 8, Redis Stack, Neo4j 5 (roles), RabbitMQ, ScyllaDB (audit), Docker Compose |
| `PickarooFrontend` | Public storefront at `/` and the staff/admin dashboard under `/app`. | React 19, Vite, TypeScript, Tailwind, Apollo Client 4, react-i18next, Vitest |
| `Pickaroo` | The Android app (customer, shop staff and driver modes). Still runs on its own **in-app mock** of the API; switching it to the real backend is epic E9. | Kotlin, Jetpack Compose, MVVM, osmdroid, Fused Location |

Contract between backend and clients: `PickarooAPI/schema/api.graphql` (generated; never edit by hand). Clients translate API errors by `extensions.code`, never by the Spanish `message`. Both clients ship in Spanish and English.

## 2. Getting everything running

Prerequisites: Node 24, Docker Desktop, JDK 17 (Android Studio's bundled one works), Android Studio with the Pixel_10 emulator (Android 17).

### Backend

```bash
cd PickarooAPI
docker compose up -d                 # MongoDB, Redis, Neo4j, RabbitMQ, ScyllaDB (ScyllaDB needs ~1 min)
npm install
# Create the three .env files from the examples (they are git-ignored):
#   gateway/.env, services/mongoAPI/.env, services/auditAPI/.env   <- copy each .env.example
#   in mongoAPI/.env: put the MongoDB password from docker-compose.yml into MONGODB_URI,
#   set JWT_SECRET (same value in auditAPI/.env), and SEED=true the first time.
npm run dev                          # gateway :4000, mongoAPI :4001, auditAPI :4003
```

- Tests: `npm test` (unit, offline, ~540 tests + `schema:check`) and `npm run test:integration` (~140 tests; starts its own copy of the API on ports 5000/5001/5003 with database `pickaroodb_it` and Redis db 1, needs the Compose containers up, ~2.5 min, cleans up after itself and checks your dev data is unchanged).
- After changing a `schema.graphql` run `npm run schema:build` and commit `schema/api.graphql` in the same commit.
- `npm run migrate` runs the data migrations on their own (they also run at startup).
- Never run `docker compose down -v` (deletes the data volumes).
- Demo users (development-only; passwords are in README section 11): `admin@carnyfrut.mx`, `gerente@carnyfrut.mx`, `empleado@carnyfrut.mx`, `repartidor@carnyfrut.mx`, `repartidor2@carnyfrut.mx` (all store "CARNYFRUT Centro"), `empleado@lahuerta.mx`, `gerente@lahuerta.mx` (store "Frutería La Huerta"), and `cliente@demo.mx`.
- Other Docker projects on the same machine can hold the same ports (27017, 6379, 7687, 5672, 9042...). Stop them first.

### Dashboard

```bash
cd PickarooFrontend
npm install
npm run dev                          # http://localhost:5173, talks to http://localhost:4000/ (VITE_GRAPHQL_URL)
npm test; npm run lint; npm run typecheck; npm run build
npm run schema:sync && npm run codegen   # after the API schema changes; commit the generated src/gql
```

Boot the emulator yourself from Android Studio. From the emulator the host's backend is `http://10.0.2.2:4000/`. The mock users in the app (password `demo1234`) are `customer1`, `staff1`, `owner1`, `driver1`.

## 3. Rules we work by

- **Git:** one Jira task = one branch (`codex/PIC-<n>-<slug>`) = one commit, created from `main`; commit message starts with the task key; stage explicit paths; no co-author or "generated by" lines anywhere (commits and PR texts). Work lands on `main` through a pull request (merge commit), never by pushing to `main`; never force-push.
- **Before merging a task:** run its tests yourself, get a read-only review of the diff (we used a reviewer agent and fixed what it found inside the same commit), and for UI do a browser or emulator pass against the real backend.
- **Jira:** project PIC at carloruiz.atlassian.net. Move tasks to In Progress when you start and Done when merged; add a comment with the PR and the test counts.
- **Languages:** no hard-coded user-facing text. Dashboard: `src/i18n/es.json` and `en.json` (a test fails on missing keys). Android: `values/strings.xml` (English) and `values-es/strings.xml`.
- **Errors:** every error the API returns has a stable `extensions.code` from the catalog in `PickarooAPI/services/mongoAPI/src/domain/errors.js` (documented in the README). A guard test fails the build if code throws without a catalog code.
- **API changes** are additive where possible; list any breaking schema change in the PR text, because both clients consume the file.

## 6. Decisions worth knowing

- Marketplace, not one business with branches: products and packages belong to one store; one store per cart and per order; categories are global and only ADMIN creates them.
- Sessions: 1-hour access token plus a 30-day rotating refresh token. A spent token inside a 10-second grace window is answered with the same result (lost-response retry); outside it the whole device family is revoked.
- An order in delivery always has an assigned driver; a driver holds at most one active delivery (unique partial index); delivery orders go READY, IN_DELIVERY, DELIVERED (no skipping).
- Order history (`statusHistory`) is written in the same atomic update as the status change. The order's own customer sees `byRole` but not who.
- Dashboard permissions are checked from `access.permissions`, never role names.
- The API menu (`login.menu`) is the source for the dashboard sidebar; its paths map to `/app/...`.

## 7. Known gaps and traps

- **The Android emulator degrades over hours** (graphics process at 100% CPU, tests then time out). Cold-boot it from Device Manager before a long test run. Instrumented tests uninstall the app afterwards; reinstall with `installDebug`.
- **Android per-app language and tests:** on Android 13+ AppCompat only applies the per-app locale while an AppCompat activity is alive, so test clean-up must clear it through `LocaleManager` (see `PikarooTestRunner`).
- Windows line endings: git warns "LF will be replaced by CRLF"; harmless. `.gitattributes` keeps generated files LF.
- Cancelling an order restores stock after the status write, not atomically with it; a crash in between leaves stock unrestored (PIC-112).
- A driver whose phone dies after pickup holds their delivery slot until staff cancel the order or ADMIN delivers it; reassigning an in-delivery order is not built.
- The dev API runs with stack traces in error responses; disable before any deployment (PIC-112). CORS is open for development.
- The dashboard has no refresh-token handling yet (it signs out at the 1-hour expiry); the API supports it.
- Product and category names in the seed are Spanish data and show as such in the English UI.
- `node --watch` restarts the dev API when any imported file or `package.json` changes; do not edit the checkout the dev API runs from while someone is using it (we used a second git worktree for work in progress).
